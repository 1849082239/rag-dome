# RAG：检索增强生成

## RAG 是什么

RAG（Retrieval-Augmented Generation，检索增强生成）是一种让大语言模型基于外部知识回答问题的技术路线。它的核心思想很简单：模型训练时没见过的知识（企业文档、私有数据、最新资讯），在问答时临时检索出来，拼进提示词里一起交给模型。

相比直接微调模型，RAG 有三个明显优势：第一，知识可更新，文档变了重新建索引就行，不用重新训练；第二，回答可追溯，可以标出答案来自哪份文档；第三，幻觉更少，因为模型被约束在"只根据资料回答"。

## RAG 的完整流程

一个完整的 RAG 系统包含离线和在线两个阶段。

离线阶段（索引构建）：首先是文档加载与解析，把 PDF、Word、网页等各种格式转成纯文本；然后是文本切分，把长文档切成几百字的小块（chunk）；接着用 Embedding 模型把每个 chunk 转成向量；最后存入向量数据库，并建立索引。

在线阶段（问答）：用户提问后，先把问题也转成向量，在向量库中检索最相似的 top_k 个 chunk；可选做一次重排（rerank）提高精度；然后把问题和检索到的上下文拼成提示词，交给大模型生成答案；最后把答案和引用来源一起返回给用户。

## RAG 的常见问题

RAG 落地时最常见的问题有三类。检索不准：切分太粗导致关键信息被淹没，或者 embedding 模型对领域术语不敏感，解决办法是调切分策略、换领域 embedding、加混合检索和重排。模型幻觉：即使给了资料，模型还是会编造，解决办法是强化提示词约束、降低 temperature、要求标注来源。成本和延迟：每次问答都要走 embedding、检索、LLM 三步，解决办法是缓存高频问题、选更小的模型、做流式输出优化体验。
