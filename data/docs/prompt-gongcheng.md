# Prompt 工程要点

## System Prompt 的作用

System Prompt 是在对话开始前给模型的"角色设定和行为约束"，它决定了模型的回答风格和边界。一个好的 System Prompt 通常包含四部分：角色定义（你是谁）、任务描述（要做什么）、约束规则（不能做什么）、输出格式（怎么呈现）。

在 RAG 场景里，System Prompt 最重要的约束是"只根据提供的资料回答，不知道就说不知道"。没有这条约束，模型遇到资料缺失时会一本正经地编造，这是 RAG 幻觉的主要来源之一。

## 结构化输出

让模型输出 JSON 等结构化格式，是 Agent 和工程化应用的基础。做法有两种：直接在提示词里要求"只输出 JSON"，或者用模型的 JSON Mode / Function Calling 能力。后者更可靠，因为是模型级别的约束。

结构化输出的要点是：在提示词里给出字段说明和示例（few-shot），并在代码里做解析校验，解析失败时重试或降级处理。

## 上下文管理

模型的上下文窗口是有限且昂贵的，RAG 的上下文管理有三招：精选，只放 top_k 个最相关的 chunk，而不是越多越好；压缩，对长文档先做摘要再喂给模型；截断，按 token 数算好预算，超了就从最不相关的开始丢。

另外一个技巧是把最重要的信息放在开头和结尾，因为模型对中间位置的信息注意力最低（"lost in the middle"现象）。

## 降低幻觉的组合拳

单靠提示词不够，生产环境通常组合使用：检索侧保证资料相关（调切分、加 rerank）；提示词侧强化约束（只根据资料回答、要求标注来源）；参数侧降低 temperature（0.1～0.3 让输出更稳定）；后处理侧做答案校验（关键词检查、引用存在性检查）。
