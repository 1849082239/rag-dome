# Embedding 与向量数据库

## 什么是 Embedding

Embedding 是把文本转成高维向量（通常几百到几千维）的技术。语义相近的文本，它们的向量在空间中的距离也近。比如"苹果手机"和"iPhone"的向量距离很近，而和"苹果树"就比较远。

RAG 用 Embedding 实现语义检索：用户问题转成向量后，在向量库里找距离最近的文档块，即使问题和文档用词完全不同，只要语义相关就能命中。这是它比关键词搜索强大的地方。

## 常用 Embedding 模型

英文场景常用 OpenAI 的 text-embedding 系列；中文场景推荐 BAAI 开源的 bge 系列（如 bge-m3），中文语义理解好，而且支持多语言。选型时要看三个指标：评测榜单分数、向量维度（维度越高越准但越占存储）、推理成本。

## 向量数据库

向量数据库专门存储和检索高维向量，核心能力是 ANN（近似最近邻）搜索，能在百万级向量中毫秒级找到最相似的。常见选型有：Chroma（轻量，适合原型和中小项目）、Milvus（分布式，适合大规模生产）、Pinecone（云服务，免运维）、pgvector（PostgreSQL 插件，适合已有 PG 的团队）。

## BM25：关键词检索的经典算法

BM25 是信息检索领域的经典算法，不依赖向量，纯粹看关键词匹配。它的打分考虑三个因素：词频（TF，词在文档中出现越多分越高，但有饱和上限）、逆文档频率（IDF，越稀有的词权重越高）、文档长度归一化（同样词频下，短文档得分更高）。

BM25 的优势是对精确词（人名、产品型号、数字）非常敏感，而这恰恰是向量检索的弱项。所以生产级 RAG 经常做混合检索：向量检索保证语义召回，BM25 保证关键词精度，两者加权融合。
