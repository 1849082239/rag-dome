# AI Agent 基础概念

## Agent 是什么

AI Agent（智能体）是能自主使用工具、多步骤完成任务的 AI 系统。和普通 LLM 应用最大的区别是：普通应用是"问一句答一句"，Agent 是"给一个目标，自己规划步骤、调用工具、检查结果，直到完成"。

比如让 Agent"帮我整理这周的销售数据并出份报告"，它会自己拆成：查数据库 → 拉数据 → 做统计 → 写报告 → 发邮件，中间调用多个工具，人只在关键节点确认。

## Agent 的核心能力

一个完整的 Agent 通常具备四种能力。规划（Planning）：把大目标拆成可执行的小步骤，常用 ReAct 模式（思考 → 行动 → 观察，循环）。工具调用（Tool Calling）：通过函数调用使用外部能力，如查数据库、调 API、读写文件，工具的描述（schema）写得越清楚，模型调用得越准。记忆（Memory）：短期记忆是对话上下文，长期记忆是向量库里的历史经验，让 Agent 越用越聪明。反思（Reflection）：执行失败时自己分析原因、调整策略重试。

## 单 Agent vs 多 Agent

简单任务用单个 Agent 就够了。复杂任务可以用多 Agent 协作：比如一个负责规划、一个负责执行、一个负责审核，像一个小团队。框架如 CrewAI、LangGraph 都支持多 Agent 编排。

多 Agent 的代价是复杂度和成本都上升，调试也更难。所以选型原则是：能用工作流（固定流程）就别用 Agent，能用单 Agent 就别用多 Agent。

## Agent 落地要过的几道坎

第一是稳定性：模型偶尔会调错工具、传错参数，需要参数校验、重试、人工确认等兜底。第二是成本：多步骤推理的 token 消耗是普通问答的几倍甚至几十倍，要做步骤裁剪和模型分级（简单步骤用小模型）。第三是安全：Agent 能调工具就意味着能"搞破坏"，必须做权限控制、沙箱隔离、操作审计。第四是评测：Agent 的效果不像分类任务那样好量化，需要设计任务成功率、步骤准确率等指标，并积累回归测试集。
